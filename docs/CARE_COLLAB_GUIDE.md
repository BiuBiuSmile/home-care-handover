# 安護交班｜個案照顧檔案與交班討論（第一、二階段）

本功能已接入現有的 `index.html`、`portal.js`，並新增 `case-collab.js`、`case-collab.css`。資料保存在既有 Supabase 專案，而非 GitHub / 瀏覽器 localStorage。

## 操作流程（使用虛構測試個案）

1. 管理員先進入「個案服務人員指派」，把主責居服員 A 和代班居服員 B 指派給同一位**測試個案**。
2. A 登入後，選擇個案 → **照顧檔案**。填寫類別、重點標題、具體照顧方式，點「提交重點給居督確認」。
3. 重點會先進入 **待確認**，不能被當成正式照顧指示；已指派的居督（或管理員）可以按「審核通過」或「退回」。被通過的內容才顯示於「已確認的照顧重點」。
4. B 進入同一個案 → **交班討論**，可提出問題、回覆、補充，討論訊息會保存建立者與建立時間。點「↻ 更新對話」可手動讀取最新訊息；開啟討論區時也會定期檢查。
5. 在討論下方點「整理為照顧重點」，會將該則討論帶入**未提交的草稿**。請先校對內容，再按提交並由居督審核。對話本身不會自動變成照顧指示。
6. 在 **正式交班** 標籤可繼續使用原有交班建立、歷史查閱與手動已讀確認。新代班人員 C 在獲指派權限後，也能看到同一個案的已確認重點與歷史討論。

## 資料表

- `public.case_care_guide_items`：照顧提案，包含案號、類別、標題、內容、作者、建立時間、`pending/approved/rejected` 及審核者／審核時間。
- `public.case_discussion_messages`：個案專屬交班對話，包含案號、作者姓名、訊息類型、內容、回覆的訊息 ID、建立時間。
- 以上兩個資料表都啟用 PostgreSQL RLS；只允許完成帳號啟用且被指派的居服員／居督查閱。管理員可查看全部個案。
- 交班對話及提案內容**不允許修改或刪除**。照顧提案僅能由有權限的居督／管理員更改審核狀態，內容不會因審核被覆蓋。
- 作者 ID 在離職刪除帳號時可設為 NULL，顯示用作者姓名與歷史內容保留。
- 新增資料表的 INSERT 觸發器由伺服器擷取登入者身份，不信任前端提交的作者姓名。跨個案留言引用會被資料庫拒絕。
- 不開放未登入或未被指派的人員讀取。管理員操作不依賴前端隱藏按鈕判斷。

## 上線提醒

- 目前是第一、二階段的**測試版**。請勿填入真實個案病史、詳細健康資料、身分證、地址或其他敏感個資，直到完成機構法遵、資安、權限與備份驗證。
- 交班討論不是即時緊急通報系統；急迫異常需依機構程序立即聯絡督導／家屬／醫療人員。
- 網站目前支援 **每 25 秒更新（僅討論開啟且畫面可見時）與手動更新**，不等於推播或完整即時聊天。
- 正式使用前仍需補強完整操作稽核、帳號撤權後 Session 檢查、監管責任、資料更正流程、通知、備份、服務期間與資料保留政策。
- 照顧重點僅供交班參考，不取代長照核定計畫、醫囑或正式照顧紀錄。
