# 安護交班｜管理員設定員工密碼（測試版）

本系統是 GitHub Pages + Supabase Auth + PostgreSQL 的獨立居家服務交班研究專案。

## 正式員工登入

- **登入帳號**：台灣手機門號（09xxxxxxxx；系統轉換成國際格式）。
- **登入密碼**：由管理員建立人員帳號時自行設定（10～72 字元，包含英文字母與數字）。
- **不開放自行註冊**。新建員工登入後不再被系統強制要求更改密碼。
- 管理員可在「帳號與權限管理」清單按「重設密碼」，為**居服員或居督**輸入新密碼。
- 重設後舊密碼不能再用於「重新登入」。既有已登入工作階段是否立即失效，仍應透過 Supabase Session 管理及後續安全設定確認。
- **新增員工及重設密碼均允許身分證字號格式**（10 字元英數），不再因這個格式拒絕；但真實身分證字號可能被取得，**不建議作為長期登入密碼**。密碼僅交由 Supabase Auth 保存雜湊值，員工資料表不新增身分證欄位，員工清單亦無法看到舊密碼。

## 如何新增員工

1. 管理員使用自己的帳號登入 [安護交班](https://biubiusmile.github.io/home-care-handover/)。
2. 開啟「管理員後台」→「建立員工帳號」。
3. 輸入**員工姓名、手機門號、角色、密碼、確認密碼**。
4. 按「建立員工帳號」，由 Supabase Edge Function `admin-create-staff` 驗證管理員身份及密碼規則後建立帳號。
5. 經核准的員工可用手機門號與管理員設定的密碼登入。管理員應以安全的私下管道交付密碼。

## 管理員刪除員工帳號

1. 在「管理員後台」→「帳號與權限管理」找到居服員或居督。
2. 按 **刪除使用者**，會顯示員工姓名及刪除影響。
3. 必須輸入 **刪除** 兩字才可送出；按下後後端再次檢查管理員權限。
4. 刪除時，Supabase Auth 使用者及手機登入資料、個案指派與該使用者的已讀紀錄一併移除；**過往交班內容及已記錄的作者姓名會保留**。
5. 操作先記錄在 `public.admin_account_events` 中；該表啟用 RLS，不對一般使用者開放直接存取。

**無法復原**：刪除後不能恢復原使用者身分。若員工只是離職或暫停服務，也可先在帳號管理頁取消勾選「啟用」或取消個案指派。
**安全限制**：不能刪除自己或管理員帳號，僅限居服員／居督。歷史交班保留不代表手機上已讀取的資料會被遠端清除；正式營運仍須採用短時效存取權杖與裝置存取控制。

## 如何重設現有員工的密碼

1. 在「管理員後台」→「帳號與權限管理」找到居服員或居督。
2. 點「重設密碼」後，輸入新密碼並再次確認。
3. 儲存成功後，告訴員工使用新密碼登入。
4. 這個功能不支援變更另一位管理員或自己帳號的密碼。管理員本人的密碼請透過個人 Auth 流程管理。

**重要：管理員知悉員工密碼代表可冒用員工身分，資安風險高於由員工自行設定的方式。** 正式上線應補充多因素驗證、密碼重複使用防護、登入與交班稽核、密碼重設通知、session 管理、停權處理及內部帳號管理規範。勿在公開群組或截圖中傳播密碼。

## 原有初始化管理員

如已使用 `bootstrap-admin.html` 建立臨時 Email 初始化管理員，請先建立並驗證一個可用的手機管理員帳號後，再停用臨時帳號及移除初始化入口。

已存在的舊測試帳號可能仍保留「必須改密碼」狀態；管理員可透過「重設密碼」功能設定新密碼，完成後解除舊帳號該狀態。

## Supabase 系統設定

- 員工帳號與密碼由後端 `auth.admin.createUser` / `auth.admin.updateUserById` 處理，只有 Edge Function 讀取 Service Role Key，不放到 GitHub。
- `profiles.must_change_password` 欄位保留，以支援先前版本帳號及臨時初始化帳號。**新版管理員建立的員工帳號會設為 false**。
- 全部交班資料仍受 RLS 控制，只有啟用且具有個案指派權限的人員才能查閱。
- Supabase 必須允許手機門號與密碼登入；需將 **Allow new users to sign up** 關閉，阻止自行註冊。
- 雖然已部署程式並完成靜態檢查，仍須用**虛構帳號**做一次端到端登入、建檔及重設測試，之後才可用真實個案資料。

## 資料保護

目前為研究測試版本，尚未完成資安與法遵驗證。個案照顧資訊可能含敏感健康資料；正式上線前需要內部作業規範、稽核、備份、保留期限與帳號撤權機制。
