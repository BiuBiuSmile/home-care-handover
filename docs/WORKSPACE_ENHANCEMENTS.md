# 大安心交班｜工作台優化（2026-11-17）
本次加入四項功能，不改變既有點數、交班審核、聊天室期限、13 款徽章。

## (1) 未讀交班提醒中心
- 工作台呈現目前帳號可讀的「最新正式交班未讀」與進行中的「受邀交班室」。
- 緊急等級優先；點擊後直接開啟個案正式交班或受邀聊天室。
- 此提醒不是推播、簡訊，也不得取代緊急通報。

## (2) 居督集中審核
- 僅限主管與管理員進入；以 PostgreSQL RLS / security_invoker view 取得正式交班待審。
- 照顧重點查詢既有 pending 狀態，沿用 RLS 與審核觸發器。
- 到期聊天室引導至原本整理介面，需核對雙方實際留言才可發佈。
- 不直接寫入點數或變更原有審核與領獎規則。
- 清單每類最近 100 筆，介面先顯示 12 筆，更多資料仍應至原本管理介面檢視。

## (3) 手機快捷操作
- 在螢幕寬度 780px 以下顯示「我的個案、待閱交班、新增交班、我的成就」。
- 快速新增交班必須先從使用者已授權的個案清單選擇個案。

## (4) 結構化交班與雲端草稿
- 使用者手動選擇精神、飲食、行動、情緒、安全及接班提醒；未勾選的項目不會推測。
- 手動「帶入下方交班內容」，仍由使用者檢查、編輯並送出正式交班。
- 暫存交班文字、類型、重要程度及日期於 `public.handover_drafts`，每個使用者／個案一筆，授權受 PostgreSQL RLS 保護。
- 草稿只存在 Supabase，沒有儲存於 browser localStorage；照片暫存不保存，重新開啟須重選。
- 完成正式交班才會刪除該個案的草稿；儲存失敗不應關閉尚未送出的表單。
- 資料庫 migration: `add_care_workspace_drafts_and_pending_review_view`，並新增 `review_pending_handovers` security_invoker view。

## 現場驗收
1. A 員工帳號僅能看自己的已授權個案提醒與私人草稿；B 不應看到 A 的草稿。
2. 用未讀交班實測點擊定位與標記已讀後消失。
3. 居督與管理員驗證待審清單、重複審核防護以及已退回內容不重複出現。
4. 在兩支手機測試新增交班、暫存恢復、離線錯誤及照片需重新選取。
5. 離職或解除個案指派後，原帳號不得繼續讀取該案草稿。
6. 暫停／刪除或改權限時，確認資料的撤權及保存政策。

**注意：** 不能只用 GitHub 提交或 SQL 結構測試，聲稱完成跨帳號實際驗收；正式投入敏感長照資料前仍需完整法遵與安全測試。
