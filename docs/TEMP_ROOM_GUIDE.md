# 安護交班｜48 小時自行開啟臨時交班室（測試版）

正式網站：https://biubiusmile.github.io/home-care-handover/

## 居服員 A：不用等居督指派 B

1. 管理員只需要**事先把個案指派給主責居服員 A**。接班居服員 B 必須有正常啟用的登入帳號，**不必事先被指派該個案**。
2. A 登入 →「交班工作台」→ 開啟自己已指派的個案 →「24 小時臨時交班室」**改名為「48 小時臨時交班室」**。
3. 填寫交班主題，從選單選擇接班居服員 B →「建立 48 小時交班室」。
4. 系統寫入 A／B 身分、個案名稱、建立時間與到期時間（建立後 48 小時）；A 可立即寫入交班文字。
5. 聊天室不提供提前關閉；固定到期後停止新留言，對話保留、不刪除。

## 居服員 B：搜尋受邀個案

1. B 使用自己的手機帳號登入 →「交班工作台」首頁的「受邀臨時交班」。
2. 輸入**個案姓名**或交班主題搜尋。**只會列出 A 已明確邀請 B 的聊天室**，不是所有個案；不能只猜姓名取得其他個案資料。
3. 點選該聊天室，閱讀 A 的交班文字；48 小時內可直接回覆。
4. B 不會因被邀請而獲得該個案完整資料的永久權限。**48 小時到期後，若 B 仍未獲正式指派，受邀聊天室入口會撤除**；歷史文字仍留存在資料庫供居督／管理員整理。

## 居督／管理員：到期後整理成最新正式交班

1. 有該個案權限的居督或管理員 → 進入個案 →「48 小時臨時交班室」。
2. 交班室到期後，會出現「居督／管理員整理正式交班」表單。
3. 閱讀 A／B 原始對話，人工確認後輸入摘要標題及整理內容，點「確認並發佈最新正式交班」。
4. 系統將整理內容新增到個案的「**正式交班**」歷史中，保留發佈者與日期。原始聊天室不被覆蓋；**每間聊天室只能發佈一份正式整理**，以防重複。
5. 一般居服員不能執行整理發佈；權限由 Supabase 資料庫檢查，不靠前端隱藏按鈕。

## 資料保存與權限

- 新開聊天室的 **48 小時**期限由 PostgreSQL 設定、判斷與拒絕逾期寫入；瀏覽器倒數只是顯示。
- 已存在的**舊版 24 小時交班室保持原到期時間與歷史內容**，不會被改寫。
- 活躍聊天室：A 必須仍被指派個案；B 只需為受邀且啟用帳號。具該案權限的居督與管理員可查看但不能冒用 A／B 發文。
- 逾期後：只有仍有**個案存取權限**的員工、居督和管理員可以查閱歷史。未獲永久指派的 B 不再可以讀取。
- 透過 RLS、受邀參與者判斷、資料庫觸發器阻擋未授權查看、發文與擴大授權。
- 無法任意修改已送出的聊天訊息、參與者、期限或歷史發文時間。
- 討論室目前約 **15 秒輪詢**（頁面開啟時）；尚未提供推播通知、圖片、附件或音訊。

## 測試與注意

已在資料庫實際模擬已指派 A 建立聊天室、未指派 B 留言，確定 **B 只可讀聊天室、不能讀整份個案，期限為 48 小時**，測試交易已完全回滾。管理員將到期聊天室摘要寫入正式交班的交易測試亦通過並回滾。前端使用虛構 A／B 與居督完成流程模擬。

但**尚未使用兩支真實手機及不同員工帳號進行完整端對端驗證**。本版應先用虛構個案測試；正式處理真實長照個案前，仍須完成資安、個資法遵、工作流程、備份、撤權及資料保存政策評估。

急迫異常或跌倒事件必須即時聯絡督導，**聊天室不能代替緊急通報**。
