# 安護交班｜24 小時臨時交班室操作說明（研究測試版）

## 使用網址

正式 GitHub Pages：https://biubiusmile.github.io/home-care-handover/

進入「交班工作台」→ 選擇個案 → **24 小時臨時交班室**。

## 使用流程

1. 管理員先在「個案服務人員指派」中，將主責居服員 A、代班居服員 B 皆指派到同一位**虛構測試個案**，並確保兩人的帳號已啟用。
2. A、B 其中一人（或該個案有權限的居督／管理員）進入該個案的臨時交班室分頁。填寫交班主題、選擇 A 與 B，點「建立 24 小時交班室」。
3. A、B 使用自己的帳號，在交班室相互留言；畫面每 15 秒在分頁開啟時檢查新內容，亦可手動更新。**這是短間隔更新，非即時推播。**
4. 雙方交接完成後，各自按「我已完成交班」。**兩人都按下確認**，交班室就提前關閉。
5. 如果沒雙方確認，交班室從建立時間起 **24 小時後自動停止接受新訊息**。後端使用 Supabase PostgreSQL 的 `now()` 判斷；不依賴使用者裝置時間。
6. 關閉後交班內容**不會刪除**，所有訊息轉為唯讀。未來獲指派同個案的居服員 C 可以查閱過往的已結束交班室。
7. 討論內容如有需要，可以點「整理成照顧重點」，將訊息帶入照顧檔案**未送出的草稿**。經本人校對並由居督／管理員審核後，才列入正式照顧重點。

## 存取與安全規則

- 活躍交班室：只有 A、B、獲授權的居督及管理員能查看；**只有 A、B 可以發送訊息或確認交班完成**。
- 結束／到期交班室：目前對該個案有存取權的服務人員可以查閱。交班歷史不會開放給未指派的員工。
- A、B 必須為已啟用且被指派到該個案的居服員；同一個案同一對 A、B 不能重複建立同時進行中的交班室。
- 建立時間、到期時間、參與者姓名與作者姓名由伺服器寫入。使用者無法更改時效、參與者、歷史訊息或發文時間。
- 管理員及居督可查看進行中的對話，但不會被允許假冒 A、B 發文。
- 交班室「關閉」由資料庫時間與寫入條件判斷。到期後資料列中的 `closed_at` 不一定有值，但權限已立即變成唯讀。雙方提早確認時 `closed_at` 會記錄關閉時間。
- 交班室目前只支援文字，未加入照片、附件、影片、推播通知、服務排班自動媒合或緊急通報。

## Supabase 新增資料

- `public.handover_rooms`：個案、A/B 參與者、建檔者、24 小時到期時間、雙方確認時間、提前關閉時間、姓名快照。
- `public.handover_room_messages`：交班室訊息、作者姓名、發文時間，採唯新增設計。
- `public.list_case_handover_staff(p_case_id)`：只回傳該個案已指派且可用的居服員姓名及 ID。
- 兩張新資料表均啟用 RLS；以 `public.can_access_case` + 交班室參與者、角色與伺服器時間再次授權；不提供匿名讀取。

## 測試與營運注意

此版本已通過程式語法、權限結構與使用虛構 A／B 的前端模擬操作測試，但**尚未完成兩個真實帳號的跨裝置端對端驗證**。請先使用虛構個案與測試帳號。

聊天室不得替代正式照顧計畫、醫囑或原有正式交班紀錄。發現急迫異常、跌倒或安全事件，仍應依機構規定立即聯絡督導或相關人員。正式處理長照個案資料前，需補足安全稽核、帳號撤權、資料保存期限、備份與適法性評估。
