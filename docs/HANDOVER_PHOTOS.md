# 安護交班｜交班照片功能（2026-11-17）

## 可使用位置

**正式交班**：進入個案 →「正式交班」→「＋新增正式交班」，在交班內容下方選擇 1～3 張照片。交班內容仍須有至少 8 字文字。送出後，圖片會附於正式交班歷史紀錄下方，點縮圖可放大。

**48 小時臨時交班室**：交班 A 建立邀請 B 的聊天室，A、B 只要在聊天室有效期間，可在「交班文字」下方選擇 1～3 張照片，與至少 2 字的文字一起傳送。聊天室到期後不再接受新圖片或訊息；已儲存的照片跟歷史訊息一起保留，查閱權限仍依原本交班室設定限制。

> 這次新增於「正式交班」及「48 小時臨時交班室」，不包含常設的「交班討論」。不因上傳照片而額外加點；原本審核點數、48 小時結束與彙整流程均不變。

## 照片規格

- 支援 JPG、PNG、WebP，單次最多 3 張；單張原始檔最大 16 MB。
- 網站上傳前使用 Canvas 轉為 JPG，最長邊縮至 1600px，通常約 2 MB 以下；重編碼會移除原圖 EXIF 與定位資訊。
- 使用 Supabase **私有** Storage Bucket `handover-photos`，限制檔案為 JPG、單張最多 2 MB。圖片不產生公開下載網址，不放在公開 GitHub 倉庫。
- 照片路徑由伺服端驗證與交班作者、個案或聊天室一致；同一則最多 3 張、不接受任意指定別人的檔案。

## 權限

- 正式交班照片：沿用 `can_access_case(case_id)`，只有授權個案人員與管理員可以下載。
- 48 小時聊天室照片：沿用 `private.can_view_handover_room`，聊天室有效期間只有受邀 A、B 或已有權限的居督／管理員。聊天室到期後依原有歷史查閱規則，不會因附圖自動授予新的個案權限。
- 照片下載經 Supabase JWT/RLS 驗證，以瀏覽器本機 Blob URL 顯示；登出會清除快取及撤銷 Blob URL。
- 僅授權人員可以新增；伺服端檢查路徑、使用者、內容格式及照片原始物件是否存在。沒有開放一般使用者任意編輯或刪除已完成交班照片。

## 操作與注意事項

1. 選擇照片後會看到送出前預覽。若要重新選擇，可以再次點選檔案欄位。
2. 同時輸入必要文字，再點選原本「儲存交班」或「傳送交班訊息」按鈕。
3. 若圖片失敗，畫面會顯示錯誤，請檢查格式、檔案大小與網路狀態，再重新提交。
4. **勿上傳未經必要性評估的個案臉部、身分證、健保卡、病歷等敏感照片。** 僅傳必要的照顧設備、擺設、傷口安全提醒等，並遵守機構告知及同意程序。
5. 緊急、跌倒、受傷或其他重大異常，仍須即時通知居督；照片不能取代異常通報。

## 資料庫變更

Supabase migrations：
- `handover_private_photo_attachments_storage_and_rls`：私有 bucket、檔案存取 RLS、兩個既有資料表的 `photo_paths text[]` 欄位，以及新增交班時的照片歸屬驗證。
- `fix_formal_handover_column_insert_privilege_with_private_photos`：補上正式交班必要欄位的 `authenticated` INSERT 權限，不允許自行寫入 `author_id` 或 `source_room_id`。

前端：`handover-photos.js`（圖片壓縮、上傳、驗證後下載及預覽）、`handover-photos.css`、`portal.js`、`handover-rooms.js`、`index.html`。

### 已驗證

- 使用資料庫回滾測試：已指派員工可上傳正式交班照片，未指派的員工不得讀取。
- 模擬 48 小時有效聊天室：受邀 B 可以提交照片，交班 A 可以查看 B 的照片；無權限使用者不能任意寫入。
- 所有資料庫測試皆在 ROLLBACK 內執行，正式個案與員工資料均未更動。
- JavaScript 語法與 HTML 元素檢查通過；跨手機實機選圖、拍照及跨帳號查看仍建議使用正式帳號驗收。
